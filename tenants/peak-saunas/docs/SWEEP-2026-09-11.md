## What STOPped or crashed before converging (fixtures 5, 6)

- **`still-levelup-4x5.png`**, 1st real attempt (`20260910-2301-still-levelup-4x5`): STOPped at
  `page_json:article` -- 2 unmatched claims, both the trigger word "medical" used in buyer-education
  prose (about what "medical-grade" claims on ads generally mean) with no claim_id and no safe
  generic synonym available. Not a Cycle 19 regression -- the same trigger-word-with-no-claim_id
  gate has flagged unrelated words in prior sweeps (see `SWEEP-2026-09-10b.md`). Re-run converged
  cleanly (`20260910-2306-still-levelup-4x5`, `attempts=3 repairs=0` across all three cartridges).
- **`still-infraredglow-4x5.png`**, 1st real attempt (`20260910-2308-still-infraredglow-4x5`):
  crashed -- `write.article failed after retry: Expecting property name enclosed in double quotes`,
  a transient malformed-JSON response from a repair call. 2nd real attempt
  (`20260910-2310-still-infraredglow-4x5`): STOPped at `page_json:article` -- the trigger word
  "reviews" (buyer-education prose about review volume/consistency, no claim_id) and a customer-quote
  paragraph citing "$200 a month" / "$2,400 a year" that the gate's incidental-numeral pass doesn't
  cover (both numbers are the customer's own cost estimate, not a verified claim). 3rd real attempt
  converged cleanly (`20260910-2313-still-infraredglow-4x5`, `article` needed 3 attempts/2 repairs,
  the other two cartridges converged on the first try).

Neither root cause is a Cycle 19 change (byline or policy default) -- both are pre-existing writer/
gate interaction patterns (a trigger word with no safe generic synonym; a customer quote's own dollar
figures outside the 1-12 incidental-numeral pass) that this sweep's real runs happened to hit, same
character as the warranty-wording STOPs `SWEEP-2026-09-10b.md` recorded before Cycle 13's fix. Not
patched under this sweep's time pressure -- flagging for a dedicated follow-up rather than guessing
at a gate change live.

## Mobile pass (390px, static checks -- Playwright/Chromium not installed on the server; not installed for this pass, static HTML/CSS checks only, per the assignment)

Checked all 23 rendered pages (`~/advertorial/tenants/peak-saunas/out/<run-id>/<cartridge>/index.html`)
against four static rules:

1. **Every `<img>` has width/height attrs, or the stylesheet has `img{max-width:100%}`.** FAIL on
   21 of 23 pages (every `article`/`longform`/`product-page` page, 3-4 `<img>` tags each; the 2
   `listicle` pages are clean -- that cartridge carries its own inline stylesheet). Root cause:
   `tenants/peak-saunas/brand/base.css` never defines an `img` sizing rule at all.
2. **No fixed CSS `width:NNNpx` above 390px on a container.** Clean on all 23 pages.
3. **The sticky CTA bar CSS has a mobile rule.** FAIL on all 7 `longform` pages (the only cartridge
   that renders `.adv-sticky-cta`) -- worse than "no mobile rule": the page's own stylesheet has
   **no rule for `.adv-sticky-cta` at all**, mobile or otherwise.
4. **No heading has `white-space:nowrap`.** Clean on all 23 pages.

**Root cause (findings 1 and 3, confirmed empirically against a real rendered page): a tenant CSS
gap, not a cartridge template bug.** `harness/render.py`'s `load_brand_css` loads EITHER the
tenant's own `brand/base.css` OR `harness/fallback.css` -- never both. `harness/fallback.css` (used
only when a tenant has no CSS of its own) defines `.adv-cta`, `.adv-sticky-cta`, and an image-safety
rule; `tenants/peak-saunas/brand/base.css` (209 lines, apparently written for the tenant's newer
`pk-*` class system per `tenant.yaml`'s `theme.root_class: pk-lp`) defines none of them. Every real
Peak Saunas page's CTA button and (on `longform`) sticky CTA bar render with **zero styling** today,
not just a missing mobile rule -- confirmed directly against `20260910-2250-hidden-costs-v2/longform/
index.html`'s own embedded `<style>` block (6733 chars, zero matches for `.adv-cta` or
`.adv-sticky-cta`). Not fixed in this cycle -- this is a tenant-CSS-coverage gap, not a `cartridges/
*/template.html` bug, so it's outside the "CSS-only, tenant-neutral cartridge template" fix scope
this cycle was authorized for; fixing it means either adding the missing rules to the tenant's own
`base.css` or changing `render.py` to layer `fallback.css`'s baseline rules under any tenant's CSS
rather than treating the two as mutually exclusive -- a real decision, not a sweep-time patch.
Flagged as a follow-up task rather than guessed at under this cycle's own time pressure.
