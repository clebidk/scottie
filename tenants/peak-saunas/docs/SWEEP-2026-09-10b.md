## Mid-sweep bugs found and fixed (both in fix 3's alternative-claim classifier)

Two real, reproducible bugs in this cycle's own fix 3 (`adv/claims.py`'s `classify_ad_claim_about` /
`_ALTERNATIVE_SUBJECT_RE`) surfaced live during this sweep, fixed on the spot, committed, and the
affected fixture re-run for a clean result:

1. **`still-levelup-4x5.png`** (first real attempt, superseded): the real ad claim `"Competing saunas
   lack red light therapy"` should have been classified `"about: alternative"` (never matched, never
   used on the page) but wasn't — the noun list only had `product`/`model`, not `sauna` — so it fell
   through to ordinary word-overlap matching and **false-MATCHED Peak's own `warranty-terms` claim at
   0.667 overlap**. That's the exact false-MATCHED-overclaim failure mode fix cycle 10 problem B closed,
   just for a competitor claim instead of a warranty one. Fixed: `sauna(s)` added to the noun list.
2. **`still-infraredglow-4x5.png`** (first real attempt, superseded): with `sauna` now covered, a
   *second* real phrasing slipped through — `"Comparison product has no red light therapy"` — because
   `"comparison"` was only ever paired with `"option"` in the noun list, never `"product"`. Same failure
   mode again: **false-MATCHED `warranty-terms` at 0.6 overlap.** Fixed by rebuilding the regex as a
   (subject word) x (noun) grid — `comparison`/`competing`/`competitor('s)` paired with every one of
   `option`/`product`/`model`/`sauna` — instead of enumerating specific combinations one at a time.

Both fixes are committed (`fcba850`, `26439ec`), covered by new tests (`tests/test_claims.py`, 3 new
tests, now 309 total passing on Mac and server), and the two affected fixtures were re-run after each
fix for a clean, accurate result — the numbers in the summary table above are from the corrected runs.
Full detail in `docs/FIXLOG.md`'s Cycle 12 "Mid-sweep correction" section, including a note flagging
this pattern (a hand-enumerated noun list kept missing real phrasings, one sweep run at a time) as worth
Caleb's attention for a more durable fix.

## Not fixed / flagging for Caleb

- **Two of seven fixtures (5, 7) didn't reach a full PASS at original sweep time**, both on the same
  pre-existing (fix cycle 6/7) `find_warranty_violations` limitation: honest warranty-education prose,
  and a shortened but not materially false warranty label/summary, both got flagged by the same bigram
  heuristic that catches a real false blanket-coverage claim, and the writer's own repair attempts kept
  reproducing the same non-compliant wording instead of converging. This cost real money at original
  sweep time (~$2.7 and ~$2.6 respectively across every real attempt) without landing a fix, because it
  was out of Cycle 12's assigned scope. **Fixed in Cycle 13** (`docs/FIXLOG.md`) with a deterministic
  pre-repair pass for this exact violation shape, no gate-logic change -- both fixtures re-run above and
  now PASS. The underlying `find_warranty_violations` bigram-heuristic false positives on honest
  education prose are unchanged by Cycle 13 (still a candidate for the same careful, example-driven
  iteration this exact function has always gotten, see
  its own extensive comments in `adv/claims.py`) rather than a rushed patch under sweep time pressure. A
  follow-up task has been spawned (task_a89f20eb, "Fix warranty-gate false positive on topical/
  hypothetical commentary") with the real failing examples from this sweep as its starting test cases.
- **Fix 4's semantic matcher reasonably declined to map `"4-in-1: near, mid, far infrared plus red light
  therapy"`** on `still-levelup-4x5.png`'s attempt (unlike the same claim's sibling wording on
  `still-infraredglow-4x5.png`, which did map). This isn't a bug — a "4-in-1" claim genuinely spans two
  separate verified claims (full-spectrum infrared + red light), and `match_claim` only supports mapping
  to one id, so the model's real, run-to-run variance between "map to the closer of the two" and "map to
  neither, since neither alone is the whole 4-in-1 claim" is a legitimate judgment call under the current
  single-id architecture, not a defect to chase down.
- **The alternative-claim classifier (`_ALTERNATIVE_SUBJECT_RE`) is still a hand-enumerated noun list**,
  even after two live corrections this sweep. See `docs/FIXLOG.md` Cycle 12's flagging note: the next new
  real phrasing (e.g. "a rival sauna" or "the leading brand" with no `comparison`/`competing`/
  `competitor` word at all) would fall through the same way. Worth considering folding this
  classification into the existing semantic-match call (fix 4) instead of continuing to patch a noun
  list one sweep at a time.
