## Cross-fixture finding: the writer never got to demonstrate a corrected overclaim this sweep

Six of seven fixtures carry at least one **plain** (non-locked-topic) unmatched ad claim -- a genuine content gap unrelated to `ad_overclaim_policy` -- and `gate_ad_brief_claims` always stops the run on a plain unmatched item regardless of policy. Only `price-comparison-v2.mov` cleared the `ad_claims` gate with zero overclaims, and it STOPped later for an unrelated writer-convergence reason (above). No fixture in this sweep produced a `REVIEW.md` with an **AD OVERCLAIMS -- page corrected, ad needs fixing** section -- every locked-topic overclaim detected this sweep was logged (`ad_claims: AD OVERCLAIM: ...` in the run log) but never reached the writer, because a separate plain-unmatched item stopped the run first every time. This isn't a bug: the `"warn"` policy only ever changes whether a *locked-topic* miss stops the run by itself; it was never going to rescue a fixture that also has a genuine, unrelated content gap. Documented here rather than fabricated -- the sweep's real finding is that these seven ad scripts currently carry more unsupported claims than `ad_overclaim_policy` alone can paper over.
