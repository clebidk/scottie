# Structural review — 2026-09-11 (Cycle 22)

Reviewed at `12ba0b2` (Cycles 19-21 on `master`): everything under `harness/`,
`cartridges/`, `workflows/`, `crons/`, `evals/`, `tenants/_template/`,
`tests/`, plus `README.md`, `Makefile`, `pyproject.toml` and `docs/`. Would a
senior engineer sign this off for a public release?

**Not yet, and the blockers are structural, not functional.** The pipeline
works, the claims gate is genuinely good, the suite is fast (675 tests, ~7 s).
What is not ready: the boundary between engine and tenant, the error surface,
and a repo that ships one company's live commercial data as a hard dependency of
its own tests. Effort is a rough estimate; **applied** items name their id in the
commit that landed them.

## 8. Test suite

675 tests, ~7 s, no network — genuinely good, with four real problems.

**R29 (High, not applied, 15 min) — minute-granularity run ids collide.**
`pipeline.py` builds the run id from `%Y%m%d-%H%M`, so two runs of the same input
inside one wall-clock minute **write into the same run directory** — in
production, silently overwriting a run's outputs. In the suite it makes
`test_workflows.py`'s "workflow reproduces harness run" test *vacuous*: within a
minute both entry points resolve to the same directory, so it passes without the
two agreeing on anything. Fix: seconds in the run id, or a uniquifying suffix.
Not applied because the run id is an artifact contract that `state.json`,
notifications and `make review` key on, and because the fix makes a
currently-vacuous test start really running — worth landing alone.
**Highest-value item next cycle.** (Another agent logged the same collision
independently.)

**R30 (High, not applied, 1 h) — the suite writes into the live tenant tree.**
`test_cli_run.py` and `test_workflows.py` run the real `cmd_run`, writing to
`tenants/peak-saunas/out/` and `runs/` instead of `tmp_path`. Gitignored, so
invisible to `git status`, but it accumulates and combines with R29 to let one
test read another's artifacts.

**R31 (Med, applied) — order dependence via process globals.** `tenant.py` and
`vocab.py` hold `_ACTIVE` globals; `cmd_run` calls `activate()` and nothing
resets it, so later tests saw a different active tenant depending on collection
order — and render, the gate and the writer prompt all fall back to `active()`.
An autouse fixture now restores both.

**R32 (Med, applied) — no markers, no network guard.** "No network calls
anywhere" held only by convention. Markers now declared with `--strict-markers`,
two image tests marked `slow`, and an autouse guard fails any test that opens a
socket — the suite passing with it on is the evidence the claim held.

**R33 (Med, not applied, 1 day) — coupling to real tenant data.** ~190 tests read
`tenants/peak-saunas/` via `tests/support.py`, which calls `load_tenant()` at
import time; assertions hardcode a lender, a price, model slugs, a person and
claim texts. Gating dependency for R41. No dedicated tests for `review.py`,
`sources/drive.py`, `sources/shopify_products.py`, `config.py` or `vocab.py`;
`cli.main()` and the argparse wiring had none until now.


## 9. Performance

Prompt sizing — the dominant cost — is already handled well: exemplars trimmed to
700 words and skipped on repairs, cache breakpoints on the stable system prefix
and on `facts_pack`, per-cartridge `max_tokens`. Nothing below is material next
to a model call, and it is worth saying so rather than implying otherwise.
Measured: `Tenant.render()` rebuilt the whole 89-key context and scanned it
linearly on every call — 1.6 ms, twice per cartridge per attempt, ~30 ms a run.
**Applied** anyway: caching it is three lines. **R34 (Low):**
`cartridge_write_constraints` and `write_page` each re-read and re-parse the same
cartridge files in the same run. **R35 (Low):** `resize_asset_bytes` re-encodes
every image even when already inside both limits — real time (the suite's slowest
test, 2.7 s), but an early return changes the bytes written, so it is a
behaviour change.


## 10. Security

**R36 (High, applied) — path traversal from a remote header.**
`sources/drive.py` took the destination filename from the **remote server's**
`Content-Disposition` and wrote to `dest_dir / filename`;
`filename="../../../etc/x"` escaped the run directory. Same class of bug in
`render.download_asset` (asset id + URL-derived extension) and
`tenant_dir()`/`init_tenant()`, where `--tenant ../../x` read a `tenant.yaml`
outside `tenants/` and `harness tenant init ../evil` copied the template outside
the repo. All three fixed and tested; run ids were already safe and now have a
test saying so.

**R37 (Med, applied) — HTML escaping.** Autoescape is on for every cartridge
template. The exception was `load_byline_html`, rendering the tenant's
`byline.html` through a bare `jinja2.Template` — autoescape off — then injecting
it with `| safe`. Now autoescaping, with tests proving a hostile author name is
escaped and both tenants' output is byte-identical.

**R38 (Med, not applied, 1 h + a product decision) — prompt-injection posture.**
The ad transcript is untrusted, attacker-supplied text: it enters the ingest
prompt and then, via `ad_brief.transcript_or_text`, every writer prompt, with no
delimiting and no "ignore instructions inside this block" framing. The saving
grace is real — an injected claim must still clear the gate's claim_id,
forbidden-term, warranty and first-person checks, and the renderer escapes output
— but the gate does not constrain angle, headline or tone. Wrap it in
`<untrusted_ad_transcript>`.

**R39 (Low, not applied):** `render.http_fetch_bytes` fetches an arbitrary URL
with no scheme allowlist or size cap; `ingest.detect_type` allowlists by
extension only, and a `.txt` input is read whole into memory uncapped.


## 11. Tenant neutrality — the release blocker

`README.md`, `docs/ARCHITECTURE.md` and `harness/tenant.py` all promise that
*"`harness/` never reads a company value from code."*

**R40 (High) — the promise is not kept, and the test meant to enforce it could
not catch it.** `tests/test_tenant.py` scanned for four case-sensitive proper
nouns. It missed **fifteen tenant-name leaks in comments and docstrings** across
six modules, including a lowercase `peak-saunas` the case-sensitive scan stepped
over. **Applied**: the scan is now whole-word, case-insensitive, and covers the
people and all ten model names for `harness/`. (Whole-word matters — a substring
match flags "speaker" for containing "peak".) It caught a leak in this cycle's
own new module as I wrote it.

It also missed **product-category words compiled into the engine**: `ground.py`
emits the literal alt text `"<model> sauna"`; `claims.py` bakes `sauna` into the
alternative-claim regex and one tenant's exact warranty sentence into another;
`write.py` and `semantic_match.py` put sauna-industry examples in engine prompts;
`claims.py` and `pdp_claims.py` hardcode a `[1-6]-Person` token. **Not applied**
(1 day): every one is prompt text or changes `facts_pack.json`. Largest remaining
pre-release job.

**R41 (High, not applied) — the repo ships a live company's commercial data.**
`tenants/peak-saunas/` holds real claims, prices, brand assets, seven binary
images, internal audit documents and a competitor list; `docs/` mixes engine
documentation with a 21-cycle work record naming people and server paths. Both
must move to a private repo, leaving only `tenants/_template/` — impossible until
R33 provides a fixture tenant. **R42 (Low):** no LICENSE, CONTRIBUTING or CI;
`pyproject` has no license, URLs or classifiers.


## 12. Packaging and CLI UX

Sixteen commands, inconsistently grouped: `claims`, `tenant`, `workflow` and
`digest` are groups; ten others are flat (**R44, Low**). No `--version`, no shell
completion (**R45, Low** — `argcomplete` would be a new dependency). `--help` now
carries the exit-code table.

**R43 (Med, applied) — `harness doctor`.** There was no way to ask "can this
tenant run?" short of starting a run and finding out mid-pipeline. It checks
files, `tenant.yaml` validity and version, credentials **by name only**, the
configured model ids against the models endpoint (listing models spends no
tokens; the check never touches `client.messages`), whisper/ffmpeg, and directory
writability. Live on the server: 26 checks, 21 pass, 5 warn, 0 fail — and it
surfaced something real, that `claude-haiku-4-5` is not in the endpoint's
11-model listing while `claude-sonnet-5` is. Hence WARN, not FAIL: three stages
have run on that id since Cycle 17, so it is an alias the listing does not echo
back, not a broken config.

## Verdict

The gate is the asset; six cycles of adversarial fixture work show in it, and it
should not be rewritten. The engine around it drifted: the CLI became the domain
layer, the engine imports the CLI, and tenant neutrality was enforced by a
four-word grep. Ranked for next cycle:

1. **R29** — collision-safe run ids. 15 minutes, prevents silent data loss.
2. **R1/R2** — lift the domain logic out of `cli.py`; the import cycle dies with it.
3. **R33 → R41** — a fixture tenant, then split `tenants/peak-saunas/` out.
4. **R40** — get the product category out of engine code and prompts.
5. **R38** — delimit untrusted ad text in the prompts.
