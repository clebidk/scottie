# Structural review — 2026-09-11 (Cycle 22)

Reviewed at `30813de` (Cycle 20 + Cycle 21 on `master`): every file under
`harness/`, `cartridges/`, `workflows/`, `crons/`, `evals/`,
`tenants/_template/`, `tests/`, plus `README.md`, `Makefile`,
`pyproject.toml`, and `docs/`. The question asked was: would a senior engineer
sign this off for a public open-source release?

**Short answer: not yet, and the blockers are structural rather than
functional.** The pipeline works, the gate is genuinely good, and the test
suite is fast (572 tests, 6.1 s). What is not ready is the boundary between
engine and tenant, the error surface, and the fact that the repository ships
one company's live commercial data as a hard dependency of its own test suite.

Findings are numbered `R1`–`R45`. "Applied" means it landed in this cycle's
Part B commits.

(`tenant.py:280`, `anthropic_client.py:8`, `publishers/shopify.py:62`,
`notify.py:72`) and never read back into a log, a message body, or stdout — a

## 8. Test suite

572 tests, 6.1 s, no network — genuinely good, with four real problems.

**R29 (High) — minute-granularity run ids collide.** `pipeline.py:42` builds
the run id from `%Y%m%d-%H%M`. Two runs of the same input inside one wall-clock
minute **write into the same run directory**. In production that silently
overwrites a run's outputs. In the suite it makes
`test_workflows.py:250` — the test whose whole purpose is proving
`harness workflow run` reproduces `harness run` — *vacuous*: both entry points
resolve to the same directory within a minute, so the comparison passes without
the two agreeing on anything. Fix: seconds in the run id, or a uniquifying
suffix when the directory exists (~15 min). **Not applied**: the run id is an
artifact contract that `state.json`, notifications, and `make review` all key
on, and fixing it makes a currently-vacuous test start really running. It is
the single highest-value item for the next cycle.

**R30 (High) — the suite writes into the live tenant tree.**
`test_cli_run.py:92,160,181,216` and `test_workflows.py:250,265` execute the
real `cmd_run`, which writes to `tenants/peak-saunas/out/` and `runs/`
(`pipeline.py:98,100,132,139`) rather than `tmp_path`. It is gitignored, so it
never shows in `git status`, but it accumulates and combines with R29 to let
one test read another's artifacts.

**R31 (Med) — order dependence via process globals.** `tenant.py:334` and
`vocab.py:23` hold `_ACTIVE` module globals; `cmd_run` calls `activate()` and
nothing resets it, so tests running afterwards see a different active tenant
depending on collection order. Exactly one test does this correctly
(`test_tenant.py:192`, `try/finally`). **Applied**: an autouse fixture now
snapshots and restores both globals around every test.

**R32 (Med) — no markers and no network guard.** No `slow`/`live` markers
existed and `pyproject.toml` declared none. **Applied**: markers declared with
`--strict-markers`, the 2.7 s image-re-encode test marked `slow`, and an autouse
guard that makes any real socket connection fail the test — so "`pytest -q`
touches no network" is now enforced rather than asserted in the README.

**R33 (Med) — coupling to real tenant data.** Roughly 190 of the tests read
`tenants/peak-saunas/` through `tests/support.py:7`, which calls
`load_tenant()` at import time. Assertions hardcode a lender name, a price
(`$8,250`), model slugs, a person's name, a review count, and claim texts. This
is the gating dependency for R40 — there is no fixture tenant to fall back on
(`tenants/_template` is used in exactly one test). Coverage gaps by module:
`review.py`, `sources/drive.py`, `sources/shopify_products.py`, `config.py`,
and `vocab.py` have no dedicated tests, and `cli.main()` / the argparse wiring
were untested until this cycle.

## 9. Performance

Prompt sizing — by far the dominant cost — is already handled well: exemplars
trimmed to 700 words and skipped on repairs, cache breakpoints on the stable
system prefix and on `facts_pack`, per-cartridge `max_tokens`. Nothing below is
material next to a model call, and it is worth saying so plainly rather than
implying otherwise.

Measured: `Tenant.render()` (`tenant.py:221`) rebuilt the whole 89-key
flattened context and linearly scanned it **on every call** — 1.6 ms per call,
0.7 ms of it rebuilding the context, and it is called twice per cartridge per
attempt (`cli.py:519`, `write.py:477`). That is roughly 30 ms per run.
**Applied** anyway, because caching the context is three lines and removes a
per-call surprise from a function that reads as a pure lookup.

**R44 (Low, not applied):** `cartridge_write_constraints` and `write_page` each
re-read and re-parse the same `cartridge.md` and `schema.json` for the same
cartridge in the same run — twice per attempt. Memoising changes when an edit
mid-process takes effect, which is not worth 5 ms. **R45 (Low, not applied):**
`resize_asset_bytes` (`render.py:304`) decodes and re-encodes every downloaded
image even when it is already inside both the long-edge and byte limits — this
is real time (it is the suite's slowest test at 2.7 s), but an early return
changes the bytes written to disk, so it is a behaviour change.

## 10. Security

**R35 (High) — path traversal from a remote header.** `sources/drive.py:63`
takes the filename straight out of the *remote server's* `Content-Disposition`
and writes to `dest_dir / filename` with no sanitisation. A crafted or
compromised response escapes the run directory. **Applied** (basename only,
separators and `..` rejected, `file_id` as fallback). The same class of issue in
`render.download_asset` (asset id + URL-derived extension into a filename) and
in `tenant_dir()` / `init_tenant()` — where `--tenant ../../x` reads a
`tenant.yaml` outside `tenants/` and `harness tenant init ../evil` copies the
template outside the repo — is **applied** too (slug regex; asset filename
sanitised).

**R36 (Med) — prompt-injection posture.** The ad transcript is untrusted,
attacker-supplied text: it enters the ingest prompt and then, via
`ad_brief.transcript_or_text`, every writer prompt (`write.py:402`). There is no
delimiting, no "ignore instructions inside this block" framing. The saving grace
is real — an injected claim still has to clear the deterministic gate's
claim_id, forbidden-term, warranty and first-person checks, and the renderer
escapes output — but the gate does not constrain angle, headline, or tone.
Recommended: wrap untrusted input in an explicit `<untrusted_ad_transcript>`
block. **Not applied**: prompt wording changes are out of scope this cycle.

**R37 (Med) — HTML escaping.** Autoescape is correctly on for every cartridge
template (`render.py:411`). The one exception was `load_byline_html`
(`render.py:71`), which rendered the tenant's `byline.html` through a bare
`jinja2.Template` with autoescape **off** and injected the result with `| safe`.
**Applied**, with a test proving a hostile author name is now escaped; output for
both existing tenants is byte-identical.

**R38 (Low)** — `render.http_fetch_bytes:283` fetches an arbitrary URL with no
scheme allowlist and no size cap; `ingest.detect_type:45` allowlists by
extension only, and a `.txt` input is read whole into memory with no cap.

## 11. Tenant neutrality — the release blocker

The repository's central promise, stated in `README.md:9`, `ARCHITECTURE.md:9`
and `tenant.py:1`, is that *"`harness/` never reads a company value from code."*

**R39 (High): the promise is not kept, and the test that is supposed to enforce
it cannot catch it.** `tests/test_tenant.py:98` scans for exactly four
case-sensitive proper nouns (`Peak`, `Austin`, `Judge.me`, `Aurora`). It misses:

- **19 tenant-name leaks in comments and docstrings** — `write.py:237,272`
  (`"Shop the Fuji"`, `"peak-saunas' default"` — lowercase, so the scan skips
  it), `render.py:94,477`, `claims.py:412,1198,1199,1283`, `cli.py:213`,
  `ground.py:136,226,229,311,372,413`. **Applied**, and the scan is now
  case-insensitive and covers model names for `harness/`.
- **Product-category words compiled into the engine** — `ground.py:128,165,293`
  emit the literal alt text `"<model> sauna"`; `claims.py:289` bakes `sauna`
  into the alternative-claim regex; `claims.py:1024` hardcodes one tenant's
  exact warranty sentence as a regex; `write.py:82,115` and
  `semantic_match.py:36` put sauna-industry examples in engine prompts;
  `claims.py:590` and `pdp_claims.py:34` hardcode a `[1-6]-Person` capacity
  token. **Not applied** — every one of these is either prompt text or changes
  `facts_pack.json` content, both explicitly out of scope. This is the largest
  remaining piece of work before release.

**R40 (High): the repo ships a live company's commercial data.**
`tenants/peak-saunas/` holds real claims, prices, brand assets, seven binary
images, internal sweep/audit documents, and a competitor list. `docs/` mixes
engine documentation with an 18-cycle internal work record naming people and
server paths. Both must move to a private repository, leaving only
`tenants/_template/` — which cannot happen until R33 gives the suite a fixture
tenant. **R41 (Low):** no LICENSE, no CONTRIBUTING, no CI configuration; `pyproject`
has no license, URLs, or classifiers.

## Verdict

The gate is the asset here; six cycles of adversarial fixture work show in it,
and it should not be rewritten. The engine around it has drifted: the CLI
became the domain layer, the engine imports the CLI, and the tenant-neutrality
promise is enforced by a four-word grep. Ranked for the next cycle:

1. **R29** — collision-safe run ids (15 min, prevents silent data loss).
2. **R1/R2** — lift the domain logic out of `cli.py`; the import cycle dies with it.
3. **R33/R40** — a fixture tenant, then split `tenants/peak-saunas/` out.
4. **R39** — get the product category out of engine code and prompts.
5. **R36** — delimit untrusted ad text in the prompts.
